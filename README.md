
# CS528 Homework 7 — Apache Beam and Google Cloud Dataflow

## 1. Project Overview

This project extends Homework 2 by using Apache Beam and Google Cloud Dataflow to analyze a collection of HTML files stored in Google Cloud Storage.

The application performs three tasks:

1. Identify the top 5 HTML files with the most incoming hyperlinks.
2. Identify the top 5 HTML files with the most outgoing hyperlinks.
3. Identify the top 5 most frequently occurring word trigrams (consecutive word triplets).

The pipeline was implemented in Python and executed using both Apache Beam's local runner and Google Cloud Dataflow.

## 5. Implementation

### 5.1 HTML Parsing

The application uses Python's `HTMLParser` to extract hyperlinks and readable text.

It handles HTML attributes such as `HREF` case-insensitively.

Script and style content is excluded from text analysis.

### 5.2 Incoming Links

An incoming link is a hyperlink from another HTML document pointing to a particular file.

For example:

```text
1654.html → 332.html
1654.html → 4736.html
```

This contributes one incoming link to each destination file.

The pipeline emits destination/count pairs and uses:

```python
beam.CombinePerKey(sum)
```

to aggregate incoming link counts.

Repeated hyperlink occurrences are counted separately.

### 5.3 Outgoing Links

Outgoing links are hyperlinks contained in a particular HTML file.

The application counts hyperlinks in each document and emits:

```python
(filename, number_of_links)
```

The five files with the highest outgoing link counts are selected.

### 5.4 Word Trigrams

A trigram consists of three consecutive words.

Example:

```text
Lorem ipsum dolor sit amet
```

Produces:

```text
lorem ipsum dolor
ipsum dolor sit
dolor sit amet
```

The implementation:

1. Extracts visible HTML text.
2. Converts text to lowercase.
3. Tokenizes words.
4. Creates consecutive word triplets.
5. Counts trigram frequencies.
6. Aggregates frequencies across the dataset.
7. Returns the five most frequent trigrams.

Words are tokenized using the regular expression `[a-z]+`.

Trigrams are generated independently for each document and do not cross document boundaries.

### 5.5 Performance Optimization

The original implementation emitted every individual trigram occurrence into the Beam pipeline.

This resulted in a large volume of intermediate records.

The optimized implementation uses Python's `Counter` to count repeated trigrams within each document before emitting them.

```python
document_trigram_counts = Counter(
    " ".join(trigram)
    for trigram in extract_trigrams(visible_text)
)
```

The resulting counts are aggregated using:

```python
beam.CombinePerKey(sum)
```

This reduces intermediate data volume while preserving the original trigram frequencies.

All top-five results are sorted by descending frequency with alphabetical tie-breaking.

## 9. Google Cloud Dataflow Execution

### 9.1 Full-Dataset Execution Challenges

The full 12,000-file dataset was submitted to Google Cloud Dataflow in multiple attempts.

During execution, Dataflow repeatedly reported straggler warnings, particularly involving stage F105.

Some runs experienced prolonged execution without successfully completing the full-dataset computation.

The following troubleshooting steps were performed:

1. Inspected Dataflow execution stages.
2. Reviewed worker logs and CPU utilization.
3. Examined Dataflow straggler insights.
4. Identified that Dataflow reported the straggler cause as "Undetermined."
5. Optimized per-document trigram aggregation.
6. Verified the optimized pipeline locally.
7. Retried the full-dataset cloud execution.

Despite these efforts, the full-dataset Dataflow jobs did not produce a successful completed result.

The unsuccessful attempts were canceled.

## 13. Observations and Lessons Learned

This assignment demonstrated several important characteristics of distributed data processing.

**1. Apache Beam portability**

The same processing logic can execute locally and on Google Cloud Dataflow by changing the runner configuration.

**2. Local aggregation improves efficiency**

Counting repeated trigrams within each document significantly reduced local processing time.

**3. Distributed processing has overhead**

For small datasets, Dataflow worker startup and resource provisioning can dominate execution time.

**4. Cloud execution can experience stragglers**

Full-dataset Dataflow runs encountered straggler warnings even after application-level optimization.

**5. Reproducibility and verification matter**

Unit tests, end-to-end tests, output comparisons, and execution logs were used to verify the implementation.
